TensorFlow vs PyTorch: Building Neural Nets and Choosing PyTorch

June 23, 2024 • 6 min • Muhammad Taha Nasir

If you've been following my journey through first-year CS, you know I've been wrestling with everything from low-level C pointers to high-level Python libraries. But this month, I finally hit a core milestone in my machine learning journey: building my first real neural networks from scratch on the classic MNIST handwritten digits dataset using both TensorFlow and PyTorch.

As a beginner trying to figure out where to focus my energy, I decided to put Google's production giant and Meta's research favorite head-to-head. Here is what happened when I built the exact same digit classifier in both frameworks and why I ultimately chose PyTorch to carry me forward.

The First Impression & Framework Setup

So, I've spent the last few weeks living inside deep learning frameworks, and if you've been tracking the AI ecosystem lately, you know that picking between TensorFlow and PyTorch feels like choosing between two completely different philosophies of software engineering.

Installing TensorFlow (tensorflow==2.12.0) on my Python 3.8 setup felt like bringing home a massive corporate tool chest. It's powerful, but it's heavy and I immediately hit a wall with dependency errors and version mismatches before I even wrote my first line of code.

Then I tried PyTorch (pip install torch). The installation was clean, the imports just worked, and the execution felt like writing standard, Pythonic code rather than configuring a locked-down enterprise engine.

The responsiveness of PyTorch's dynamic graph model is staggering you can inspect tensors at any line of code using basic Python print statements. But TensorFlow's Keras API and TensorBoard visualizations still carry serious weight. So, how do they compare when building identical models? Let's find out.

Model Architecture under the Hood in 100 Seconds

Imagine spending hours debugging a tensor shape mismatch error, only to realize your input array was missing a single dimension. Welcome to building neural networks.

Approach 1: TensorFlow & Keras Sequential API

TensorFlow's Keras API abstracts the math into high-level layers. You normalize pixel values from [0, 255] to [0.0, 1.0], stack your layers sequentially, and compile. Skipping normalization is a classic newbie trap my first unnormalized model was a complete training disaster!

import tensorflow as tf
from tensorflow import keras

# Data Loading & Normalization
(x_train, y_train), (x_test, y_test) = keras.datasets.mnist.load_data()
x_train, x_test = x_train / 255.0, x_test / 255.0  

# Keras Sequential Model Definition
model = keras.Sequential([
    keras.layers.Flatten(input_shape=(28, 28)), # 28x28 Image -> 784 Vector
    keras.layers.Dense(128, activation='relu'), # Hidden Layer with ReLU
    keras.layers.Dense(10, activation='softmax') # 10 Output Probabilities
])

model.compile(optimizer='adam',
              loss='sparse_categorical_crossentropy',
              metrics=['accuracy'])

model.fit(x_train, y_train, epochs=5) # ~97% Training Accuracy!

Approach 2: PyTorch & Dynamic nn.Module

In PyTorch, you explicitly define your network structure inside a class inheriting from nn.Module and control the forward pass manually:

import torch
import torch.nn as nn
import torchvision
import torchvision.transforms as transforms

# Data Pipelines with torchvision DataLoader
transform = transforms.Compose([transforms.ToTensor()]) # Normalizes automatically
train_dataset = torchvision.datasets.MNIST(root='./data', train=True, transform=transform, download=True)
train_loader = torch.utils.data.DataLoader(train_dataset, batch_size=64, shuffle=True)

# Explicit Object-Oriented Network Architecture
class Net(nn.Module):
    def __init__(self):
        super(Net, self).__init__()
        self.flatten = nn.Flatten()
        self.linear1 = nn.Linear(28 * 28, 128)
        self.relu = nn.ReLU()
        self.linear2 = nn.Linear(128, 10)

    def forward(self, x):
        x = self.relu(self.linear1(self.flatten(x)))
        return self.linear2(x) # Raw Logits passed to CrossEntropyLoss

model = Net()
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.01, momentum=0.9)

In PyTorch, you write the explicit training loop yourself: zero out gradients (optimizer.zero_grad()), calculate loss (loss.backward()), and step the optimizer (optimizer.step()).

If you forget optimizer.zero_grad(), your gradients accumulate across iterations and destroy your weights. Take the absolute L.

Both frameworks achieve virtually identical performance on standard datasets like MNIST. But while TensorFlow took significantly more setup and debugging effort to get running smoothly, PyTorch allowed me to start building models right away.

The Systems Engineer's Rant

LOOK AT THIS TRAINING LOOP! JUST LOOK AT IT!

I am watching new machine learning developers rely entirely on high-level abstractions without understanding how gradient backpropagation actually updates neural weights in memory, and I am physically losing my mind!

# What beginners write in TensorFlow without knowing what happens under the hood:
model.compile(optimizer='adam', loss='sparse_categorical_crossentropy')
model.fit(x_train, y_train, epochs=5) # Magic line of code! Zero insight!

You guys are out here calling model.fit() without understanding computational graphs, tensor allocations, or loss gradients!

It is NOT GOOD ENGINEERING!

This is precisely why PyTorch is winning the research community! When you write an explicit PyTorch loop, you are forced to handle tensor shapes, manually clear accumulated gradients, and compute backward passes directly.

# THIS IS HOW YOU LEARN REAL DEEP LEARNING:
optimizer.zero_grad()    # 1. Clear memory buffers
loss = criterion(out, y) # 2. Compute loss scalar
loss.backward()          # 3. Calculate dLoss/dW via chain rule!
optimizer.step()         # 4. Update weight matrices!

If you don't understand tensor dimensions, activation functions, and gradient updates, you aren't an AI engineer you're just calling a high-level API wrapper!

Stop hiding behind automated fitting scripts and learn to write your own forward passes!

The Studio Hardware Stress Test

So, training a 3-layer neural network on CPU memory for 5 epochs takes less than 30 seconds. But what happens when you accidentally mess up your batch size or dimension flattening inside a loop on a laptop setup?

To find out, I tested both frameworks under high batch sizes to see how system memory and CPU temperatures held up on my dev rig.

When you hit a tensor shape mismatch error in TensorFlow, the execution stack trace can stretch across 40 lines of internal C++ engine code, making it frustrating to pinpoint where your batch dimension went wrong. In PyTorch, standard Python breakpoints pause the exact line in your forward() method where dimensions conflict, making hardware debugging fast and painless.

Understanding your data dimensions and tensor shapes isn't just theory it's what keeps your training runs from throwing memory exceptions midway through an epoch!

Conclusion: Which Should You Choose?

As a Computer Science student navigating the deep learning landscape, I found PyTorch to be the clear personal winner for my current goals.

TensorFlow is an undisputed powerhouse for large-scale enterprise pipelines, mobile deployment via LiteRT, and production serving. But PyTorch's Pythonic syntax, intuitive dynamic graphs, and sheer dominance in the research and Generative AI ecosystem make it the ultimate tool for learning, prototyping, and building modern AI applications.

I'm sticking with PyTorch for my upcoming projects but keeping TensorFlow in my back pocket for deployment down the line.
