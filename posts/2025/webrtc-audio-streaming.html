Why WebRTC over WebSockets for Audio?

Building real-time conversational AI voice agents (like OpenAI Realtime API, LiveKit, or custom multi-modal agents) requires target end-to-end latencies under 500ms. When evaluating network protocols for live audio transport, engineers quickly hit a wall with traditional WebSockets.

WebSockets operate over TCP. TCP guarantees reliability and ordered packet delivery through mandatory retransmissions and exponential backoff. On real-world Wi-Fi or cellular networks, a single lost packet triggers Head-of-Line (HoL) blocking, holding back all subsequent audio chunks until the dropped packet is retransmitted. This manifests as sudden 300ms–1500ms latency spikes and audio stutter, breaking natural human conversation flow.

WebRTC, by contrast, is built directly on UDP-based SRTP (Secure Real-time Transport Protocol). It prioritizes timely delivery over strict reliability. WebRTC includes built-in Opus codec negotiation, dynamic jitter buffers, automatic packet loss concealment (PLC), forward error correction (FEC), and continuous bandwidth estimation. Net transport latency remains sub-100ms even under fluctuating network loss.

Protocol Dimension WebSocket (TCP) WebRTC (UDP / SRTP)
Transport Layer TCP (Reliable, Ordered) UDP / SRTP (Timely, Unreliable/Ordered Option)
Head-of-Line Blocking Severe (packet retransmission pauses stream) Zero (drops old frames, uses jitter buffer & PLC)
Transport Latency 200ms – 1200ms+ (Variable spikes) < 50ms – 100ms (Ultra low & consistent)
Codec & Media Engine Manual byte wrapping (PCM / Base64) Native Opus negotiation, sample rate control, AEC

In a full-duplex Python backend, your server acts as a peer in a WebRTC session using aiortc, an asynchronous implementation of WebRTC and ORTC in Python built on top of asyncio and PyAV.

Building a Low-Latency Async Audio Queue

WebRTC operates on strict clock intervals. Audio frames typically arrive every 20ms (320 samples at 16kHz mono PCM 16-bit, or 960 samples at 48kHz). To maintain ultra-low latency without blocking the asyncio event loop, incoming frames must be buffered, resampled, and fed into processing tasks asynchronously.

import asyncio
from aiortc import RTCPeerConnection, RTCSessionDescription
from av.audio.resampler import AudioResampler

async def process_inbound_audio(track, audio_queue: asyncio.Queue):
    """
    Reads 20ms incoming frames from WebRTC, resamples to 16kHz mono PCM,
    and pushes raw PCM bytes onto an asyncio queue for VAD/STT processing.
    """
    # Resample incoming audio (variable rate) to uniform 16kHz s16 mono
    resampler = AudioResampler(format="s16", layout="mono", rate=16000)

    while True:
        try:
            frame = await track.recv()
            # Resample frame off-thread if necessary, or process stream
            resampled_frames = resampler.resample(frame)
            for r_frame in resampled_frames:
                pcm_bytes = r_frame.to_ndarray().tobytes()
                # Push non-blocking to prevent backpressure bloat
                if not audio_queue.full():
                    audio_queue.put_nowait(pcm_bytes)
        except Exception as e:
            # Track ended or connection closed
            break

Full-Duplex Interruption & Silero VAD (The "Bidi" Challenge)

True bidirectional ("Bidi") voice pipelines require instant Barge-in / Interruption handling. When the user begins speaking while the AI model is streaming TTS audio back to the client, the backend must instantly cancel TTS output and flush all queued audio frames within 50ms.

Silero VAD (Voice Activity Detection) runs lightweight ONNX inference on incoming 20ms/30ms PCM chunks. When VAD returns a high probability of speech while the TTS stream is active, an interruption event is raised:

async def vad_interruption_monitor(
    audio_queue: asyncio.Queue, 
    outbound_track: "AsyncAudioOutputTrack", 
    current_response_task: asyncio.Task
):
    """
    Monitors inbound PCM chunks with VAD. On user barge-in, flushes
    the outbound WebRTC queue and cancels pending LLM/TTS generation.
    """
    speech_frames = 0
    VAD_THRESHOLD = 0.75

    while True:
        pcm_chunk = await audio_queue.get()
        
        # Offload heavy ONNX tensor inference to thread pool to avoid blocking loop
        prob = await asyncio.to_thread(run_silero_vad, pcm_chunk)

        if prob > VAD_THRESHOLD:
            speech_frames += 1
            if speech_frames >= 2:  # Confirmed speech onset (~40ms)
                # 1. Flush outbound audio queue immediately
                outbound_track.clear_buffer()
                
                # 2. Cancel current LLM/TTS generation task
                if current_response_task and not current_response_task.done():
                    current_response_task.cancel()
        else:
            speech_frames = 0

Streaming TTS Back via Custom AudioStreamTrack

To stream real-time audio back to the client over WebRTC, you implement a custom subclass of aiortc.MediaStreamTrack. The WebRTC RTP engine automatically calls the track's recv() method every 20ms to pull audio frames for packetization.

Below is the complete production implementation for an outbound full-duplex track consuming PCM chunks from an asyncio.Queue with silent frame fallback and instant buffer clearing:

import asyncio
from aiortc import MediaStreamTrack
from av import AudioFrame
import numpy as np

SAMPLE_RATE = 16000
FRAME_DURATION_MS = 20
SAMPLES_PER_FRAME = int(SAMPLE_RATE * (FRAME_DURATION_MS / 1000))

class AsyncAudioOutputTrack(MediaStreamTrack):
    """Custom WebRTC audio stream consuming PCM chunks from an asyncio.Queue."""
    kind = "audio"

    def __init__(self):
        super().__init__()
        self.queue: asyncio.Queue[bytes] = asyncio.Queue()
        self._pts = 0

    async def recv(self) -> AudioFrame:
        """Called automatically by aiortc every 20ms to push RTP packets."""
        try:
            # Non-blocking fetch or fallback to silent frame
            data = self.queue.get_nowait()
        except asyncio.QueueEmpty:
            data = b'\x00' * (SAMPLES_PER_FRAME * 2)  # 16-bit PCM silence

        # Convert raw PCM bytes to PyAV AudioFrame
        audio_data = np.frombuffer(data, dtype=np.int16)
        frame = AudioFrame.from_ndarray(
            audio_data.reshape(1, -1), 
            format="s16", 
            layout="mono"
        )
        frame.sample_rate = SAMPLE_RATE
        frame.pts = self._pts
        self._pts += SAMPLES_PER_FRAME

        return frame

    def clear_buffer(self):
        """Used when user interrupts, drops queued TTS frames immediately."""
        while not self.queue.empty():
            try:
                self.queue.get_nowait()
            except asyncio.QueueEmpty:
                break

Key Takeaways, Clock Drift, & Pacing Pitfalls

Designing high-throughput async Python voice pipelines comes with specific low-level engineering caveats. Keep these three core principles front and center when scaling your architecture:

  1. Never Block the Event Loop: Heavy Digital Signal Processing (DSP), sample rate conversion via soxr, or VAD neural network inference must never execute synchronously on the main asyncio loop thread. Always wrap heavy tasks in asyncio.to_thread() or offload to a ProcessPoolExecutor.
  2. Audio Clock Drift & Timestamp (PTS) Pacing: WebRTC requires precise timing in recv(). If your TTS engine generates audio faster than real-time (e.g., 5 seconds of audio produced in 200ms), do not attempt to send it all at once. Push raw PCM chunks into the AsyncAudioOutputTrack.queue and let WebRTC's 20ms consumer loop pull them at real-time clock speed.
  3. Queue Bounding & Backpressure: Always configure explicit max sizes on your asyncio.Queue(maxsize=50). Unbounded queues cause latency drift and memory growth under transient network degradation.
