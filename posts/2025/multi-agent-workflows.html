Architecting a Multi-Agent System with AutoGen and LangGraph

Moving Beyond the Chat Interface

The standard way we interact with LLMs is fundamentally flawed for complex engineering tasks. You type a prompt, the model generates an output, and you read it. If you ask ChatGPT to write a complex web scraping script involving authentication, it will output a script. But what happens if that script throws a missing dependency error when you run it?

A human developer would read the stack trace, realize the error, install the dependency, and run it again. An LLM in a single chat session cannot do this. It is a passive generator. To build systems that actually get work done, we have to move beyond passive chatbots and build autonomous agents.

The Agentic Paradigm

Agentic AI involves giving an LLM access to tools (like a Python interpreter, a terminal shell, or web search) and allowing it to iteratively solve problems. Instead of a single massive prompt, you architect a system of multiple specialized agents that communicate with each other, critique each other's work, and loop until the task is successfully completed.

I recently experimented with this by building an automated data-gathering system using Microsoft's AutoGen framework and LangGraph for state routing.

Defining Specialized Roles

If you give one agent too many responsibilities, it gets confused and hallucinates. The trick is to split the workload into highly specialized personas. For my system, I designed three core agents:

  • The Planner: Takes the ambiguous user request and breaks it down into a strict, step-by-step markdown checklist.
  • The Coder: Receives the checklist and writes the actual Python scripts. It is instructed strictly to output code, not conversational filler.
  • The Executor: A proxy agent that takes the Coder's script, executes it in an isolated Docker container, and returns the terminal output (success or stack trace) back to the Coder.

Implementing with AutoGen

Here is a conceptual look at how you define these distinct personas and initiate a collaborative loop using AutoGen:


import autogen

# Load LLM configurations
config_list = [{"model": "gpt-4-turbo", "api_key": "sk-your-key"}]
llm_config = {"config_list": config_list, "temperature": 0.2}

# 1. The Planner Agent
planner = autogen.AssistantAgent(
    name="Planner",
    system_message='''You are the lead engineer. 
    Break the user's task into a numbered list of technical steps. 
    Do not write code. Only output the plan.''',
    llm_config=llm_config
)

# 2. The Coder Agent
coder = autogen.AssistantAgent(
    name="Coder",
    system_message='''You are a senior Python developer. 
    Write clean, robust code based on the Planner's steps. 
    If the Executor returns an error, analyze the stack trace and fix the code.
    Wrap all code in standard markdown blocks.''',
    llm_config=llm_config
)

# 3. The Executor (Runs locally on your machine or in Docker)
executor = autogen.UserProxyAgent(
    name="Executor",
    human_input_mode="NEVER",
    max_consecutive_auto_reply=10,
    is_termination_msg=lambda x: "TERMINATE" in x.get("content", ""),
    code_execution_config={
        "work_dir": "./agent_workspace", 
        "use_docker": True # Crucial for security
    }
)

# Initiate the multi-agent chat
executor.initiate_chat(
    planner,
    message="Create a script to scrape the top 10 posts from HackerNews and save them to a CSV. Execute it and confirm the CSV exists."
)

The Infinite Loop Problem

Running this code for the first time was mesmerizing. Watching the Coder write a script, the Executor fail it due to a missing `requests` import, and the Coder immediately apologizing and rewriting the script with the import was incredible. It felt like watching a real engineering team work.

But then, disaster struck. The Coder encountered a web scraping bot-protection error. It tried to fix it by changing headers. It failed again. It tried again. Before I realized what was happening, the agents had locked themselves into an infinite feedback loop, rapidly burning through API credits as they repeatedly failed and retried the exact same broken approach.

State Management and LangGraph

The most difficult engineering challenge in multi-agent systems is state management and failure routing. AutoGen handles conversational turns well, but it lacks strict control flow.

To solve the infinite loop issue, I had to introduce state graphs using LangGraph. LangGraph allows you to define the agent workflow as a directed cyclic graph. I implemented hard transition guards: if an agent fails three times consecutively, the execution flow breaks out of the loop and routes to a "Human Intervention" node, pausing the system and asking me for help.

Designing agent networks feels entirely different from traditional programming. You are not writing logic; you are writing instructions for entities that write the logic. It is unpredictable, highly frustrating, but undeniably the future of software engineering.
